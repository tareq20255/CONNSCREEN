# CONNSCREEN

إدارة وتشغيل شاشات العرض (Android) في الفروع: كل شاشة تعرض محتوى مختلفًا أو مشتركًا حسب الفرع والمكان والاتجاه والموعد.
تطبيق PWA ثابت على GitHub Pages، والبيانات على Supabase (مشروع bestway-ops). مستقل عن تطبيق «من واتساب إلى ورقة».

- `index.html` — لوحة الإدارة (الشاشات، المحتوى، الفروع والأماكن، المعاينة).
- `player.html` — المشغّل الذي يفتح على الشاشة (ES5 لمتصفحات Healthmonitor القديمة).
- `src/signage-*.js` — الإعدادات والمنطق المشترك (`core`) والتخطيط (`layout`) وعميل Supabase (`api`).
- `supabase/signage_setup.sql` ثم `signage_update_2.sql` — الجداول والدوال والصلاحيات. مُنفَّذان بالفعل على المشروع.
- `sw.js` و`manifest.webmanifest` — التثبيت والعمل بدون إنترنت.

```sh
npm test   # اختبارات الوحدات والمشغّل بمتصفح وهمي
```

## ملاحظات مهمة

- **النطاق مشترك** `tareq20255.github.io` مع تطبيق الواتساب، لذلك مفاتيح التخزين `bw-signage:*` (معرّف الشاشة وجلسة المدير)
  لم تتغير فتكمل الشاشات القديمة بلا إعادة ربط. وكاشات الـ Service Worker هنا بادئتها `connscreen-` ولا تمسح غيرها.
- **الإصدار:** عند أي تغيير ارفع `APP_VERSION` في `index.html` واسم الكاش في `sw.js` و`PLAYER_VERSION` في `player.html`
  وأضف بندًا في `CHANGELOG.md` (اختبار يتأكد أنها متطابقة). الشاشات تفحص `PLAYER_VERSION` كل 6 ساعات وتعيد التحميل.
- **الأمان:** مفتاح Supabase في `src/signage-config.js` من نوع publishable فقط، والحماية الفعلية من RLS في القاعدة. لا تضع مفتاحًا سريًا هنا.
- **تعديل القاعدة:** أي تغيير يُكتب كملف SQL جديد في `supabase/` (`signage_update_3.sql` …) وتُحدَّث الاختبارات.
